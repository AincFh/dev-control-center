# ATLAS · 跨领域多项目开发路线图（2026-11-06）

ATLAS 是跨领域软件研发平台，不是游戏集合。项目覆盖系统软件、全栈网站、移动应用、工程工具与游戏；以下仅列真实存在的公开仓库，不代表各产品已完成。最新提交、Issue、PR、CI 和部署以每个 GitHub 仓库实际状态为准。

**2026-11-06 已落实跨领域发现第一批：** GitHub 星图在原游戏与模拟索引基础上新增 12 个非游戏领域（系统/Web OS、AI Agent、Windows/桌面、移动、Web/SaaS、开发者工具、自动化、数据可视化、音视频、教育、基础设施、设计）。首次从 GitHub 公开仓库检索并去重追加 465 个第三方参考名称，初始合计 2,237 条。此统计是代码内首次入库数量，不是产品完成量，也不会替代后续实际刷新与许可证审查。前台可按“软件/AI/工具”“游戏与仿真”“全部领域”切换，保留分页、收藏、详情及候选孵化。后续增量采集会根据 48 个来源查询继续拓展；具体任务见 [Issue #32](https://github.com/AincFh/dev-control-center/issues/32)。

## 跨聊天恢复

1. 从 ATLAS 查看最近同步的公开仓库数据。
2. 阅读本路线图、docs/DEVELOPMENT_PROTOCOL.md，并核对项目仓库最新主分支、PR 和 Issues。
3. 具体开发应明确仓库与 Issue，在开发分支实现，测试后 PR，获准后合并并实际检查在线预览。
4. 任何“已完成”必须附提交、构建、验收记录；绿色 CI 不等于产品成熟或发行条件满足。
5. 私有项目永远不能写入公开 Pages 状态快照，浏览器静态页不能保存或使用管理员令牌。

## 创建新项目的准入条件

只有能够交付可操作产品、测试及发布策略时才建独立公开仓库。项目数量不是成果，已交付功能和可验证质量才是成果。

## 跨领域产品组合与交付约束

研发方向至少分为：系统/OS、Web/全栈、Android/iOS 原生应用、AI/Agent、开发者工具、Windows 桌面工具、自动化与工作流、数据与可视化、创意与内容、教育学习、游戏与仿真、实验与开源基础设施。

**已有公开仓库：** dev-control-center、AincFh、my-anime-blog、QingJi、squiffy 具有非游戏研发价值。**已有但不进入公开索引：** Saintlaurent 和 shengluolan-app 均为私有仓库，禁止公开读取或展示内部内容。**仅为方向、尚无对应新仓库：** 跨领域 AI 工作流工具、Windows 系统诊断集合、内容视频制作流水线等，不得标记为产品已完成。

优先投入可验证的完整产品：真实核心流程、离线/在线状态与恢复、性能、可访问性、安全边界、自动化测试和发布策略。游戏保持独立研发，但不再占据所有首屏与优先路线。第三方仓库必须分别标注外部参考 / Fork / 原创 / 已交付。

## 2026-11-05 开源游戏引入计划

现已建立 8 个保留原始项目来源、MIT 许可的独立 Fork：天堂小岛、Cimulity、QubeCraft、虚拟宠物、Midnight Factory、Spacefortress、City of Small Chances、Squiffy。除明确说明的修改外，所有已有玩法与美术来自上游作者，不能声称属于 ATLAS 原创。浏览器实验室另有 9 个参考项目，其中许可未核验者只供调研。

优先顺序：先完成 Fork 的独立 CI / Pages 验证和版本变更日志，再补充原创功能。大型工程（城市/体素）必须保留许可证与资产来源记录，不直接并入已有游戏仓库。

## 第一批跨领域发现的验收范围

- 全部参考仓库由 GitHub 公开 repository search 返回，归类依据搜索主题；不等于人工逐仓库精确分类，不保证维护质量或授权范围。
- GitHub 星图默认显示非游戏软件、AI、工具，游戏另设可切换分组；两者都可以进入现有本地研究候选池。
- 每日自动发现仍只追加通过名称格式和去重校验的公开仓库，不直接创建 Fork，不擅自下载或合并上游源代码。
- 完整自研产品的研发和验收另按 Issue → Branch → PR → CI → 真实交互测试 → 发布执行；新增索引并不代表新产品已开发。

## 2026-11-06 跨领域外部项目实验室扩展

- 以 GitHub 公开搜索索引为来源，在原游戏/模拟项目上新增扩展至 **4,191 条仓库参考、26 个分类**；其中非游戏分类由 12 类拓展至 18 类。
- 新六类：效率/笔记与协作、通讯社区、安全与隐私、科学与工程、商业与财务、无障碍与辅助技术。
- **36 个第三方精选档案**：每个经 GitHub API 校验仓库路径、简介、技术语言、Stars、许可证标识及最近提交时间（采集于 2026-11-06）。快照不保证持续实时，也不构成许可证/素材复用授权。
- 研究 UI 提供领域筛选、动态展开、来源打开、收藏、项目孵化以及四仓库并排比较；按用户操作向 GitHub 公共 API 查询更新，错误时保留未知。
- 定时检索按领域轮换，每次最多 42 个基础主题及 9 个第二页查询；维持已有项目和名称去重，避免每日扫描时间随查询数量无限增加。
- 这些是外部研究线索，不是新建 2,000 多个原创仓库。要真正二次开发时，先核对 LICENSE、商标、素材、依赖授权及部署条件，在独立任务与仓库中记录适配方案。

## 2026-11-06 · 全领域工程蓝图（Wave 2）

- 本轮新增 16 个研究方向：数据库、云原生、物联网、机器人、GIS、电子硬件、网络协议、浏览器扩展、CLI、电子商务、测试、文档、办公、医疗技术、能源与 MLOps。统计规模 **5,132 条 GitHub 公开参考、42 个领域、52 个 GitHub API 核实的非游戏精选档案**（本次提交快照，不代表未来固定数量）。
- 为全部 42 个类别配置**独立的产品目标、核心功能、验收验证及风险**，按来源/许可、可运行验证、产品实施、质量/安全、交付维护五阶段输出。通过纯函数校验范围覆盖及 Markdown 生成；源码上游路径格式受到限制。
- 交互式星图优先显示四个领域群组，深入具体组后显示实际类别，避免 42 个轨道节点堆叠；研发蓝图支持绑定第三方来源、生成 Issue 草稿、加入浏览器本地研发候选和导出 Markdown。所有项目仍标记为未经授权审查的第三方参考。
- 分类来源为 GitHub 主题检索结果，可能有广泛和不精确项，不能认为已人工逐个核查质量、许可证或分类。精选快照仅用于初选，正式产品应核对上游源码与依赖。

## 2026-11-06 · 首批真正可用的非游戏产品能力

在 42 个领域研发蓝图之外，ATLAS 增加**浏览器本地开发工具工坊**，交付 JSON、CSV、文本差异、Unicode Base64、URL 编解码、SHA-256 及文本统计 7 个实际功能。产品必须按真实浏览器操作、输入/错误边界、性能/资源限制、移动端与导出验证，而非只看卡片或页面入口。没有云端接口、不保存用户文本，也不对外发送输入。它属于 ATLAS 平台内的子工具，不应计为 7 个已经发布的独立桌面产品。
